# OCR 服务部署运维说明

## 运行要求

- Python 3.11
- CPU 环境（RapidOCR + ONNX Runtime）
- 独立虚拟环境，不与 ASR 的 PyTorch/FunASR 环境混用
- 生产环境使用一个 worker，避免重复加载模型

## Linux CPU 部署

```bash
cd /www/famm/ocr-service
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip setuptools wheel
.venv/bin/python -m pip install --no-cache-dir -r requirements-cpu.txt
test -f .env || cp .env.example .env
mkdir -p model_cache tmp logs
```

生产 `.env` 建议：

```text
OCR_HOST=127.0.0.1
OCR_PORT=8898
OCR_AUTO_LOAD=true
OCR_MODEL_CACHE_DIR=model_cache
OCR_TEMP_DIR=tmp
```

启动：

```bash
.venv/bin/python -m uvicorn app.main:app \
  --host 127.0.0.1 \
  --port 8898 \
  --workers 1
```

首次启动时 RapidOCR 会自动下载 ONNX 模型文件。模型默认缓存于 `~/.cache/rapidocr/`，后续重启直接复用。

Java 后端和 OCR 服务位于同一台机器时，只监听 `127.0.0.1`，不要向公网开放 8898。

## Docker 部署

```bash
# 构建
docker build -t firstaid-ocr-service .

# 运行（首次启动自动下载模型）
docker run -d -p 8898:8898 --name ocr firstaid-ocr-service

# 持久化模型缓存
docker run -d -p 8898:8898 \
  -v ocr-models:/home/ocruser/.cache/rapidocr \
  --name ocr firstaid-ocr-service
```

Docker 环境变量可通过 `-e` 覆盖：

```bash
docker run -d -p 8898:8898 \
  -e OCR_AUTO_LOAD=true \
  -e OCR_LOG_LEVEL=warning \
  --name ocr firstaid-ocr-service
```

## 启动顺序

```text
1. OCR 服务
2. Java 后端
3. 前端联调
```

## 健康与业务验证

```bash
curl --fail-with-body http://127.0.0.1:8898/v1/ocr/health
curl --fail-with-body -X POST http://127.0.0.1:8898/v1/ocr/warmup
curl --fail-with-body -X POST http://127.0.0.1:8898/v1/ocr/recognize \
  -F "image=@tests/test.jpg"
```

`warmup` 后确认健康响应中的 `model_loaded` 为 `true`。

使用 tests 目录下的测试图片验证 OCR 识别：

```bash
# 直接在宿主机调用（端口已映射）
curl -X POST http://127.0.0.1:8898/v1/ocr/recognize \
  -F "image=@tests/test1.jpg"

# 或在容器内测试
docker cp tests/test1.jpg firstaid-ocr:/tmp/test1.jpg
docker exec firstaid-ocr python -c "
import urllib.request, json
with open('/tmp/test1.jpg', 'rb') as f:
    r = urllib.request.urlopen(urllib.request.Request(
        'http://127.0.0.1:8898/v1/ocr/recognize',
        data=f.read(),
        headers={'Content-Type': 'image/jpeg'}
    ))
    print(json.dumps(json.loads(r.read()), indent=2, ensure_ascii=False))
"
```

## 常见问题

- 首次请求慢：生产设置 `OCR_AUTO_LOAD=true`，或部署后调用 warmup。
- 重复下载模型：确认模型缓存目录可写且持久化；Docker 环境需挂载 volume。
- 内存过高：确认只运行一个 worker，且没有重复启动进程。
- 端口变更：同步修改 Java 后端的 `ocr.local.base-url`。
